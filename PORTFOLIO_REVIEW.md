# Portfolio Review

Documento de apoio para a curadoria profissional deste perfil.

## Objetivo

Organizar o GitHub para que a primeira impressão represente melhor o trabalho atual, separando projetos de produto, projetos de estudo e projetos legados.

## Diretrizes

- README de cada projeto deve explicar problema, solução, stack, arquitetura, execução e status.
- Projetos antigos permanecem como histórico, mas não devem dominar a vitrine.
- Projetos de cliente ou produto devem destacar decisões técnicas reais, sem inventar funcionalidades.
- Commits futuros devem usar mensagens mais descritivas e consistentes.
- Projetos em destaque devem ter screenshots, demonstrações e documentação quando possível.

## Prioridade de curadoria

1. Perfil principal (`c-o-s-m-o/c-o-s-m-o`).
2. Projetos modernos em Next.js/TypeScript.
3. Projetos de dados e automação.
4. Mobile.
5. Projetos legados e de aprendizado.

## Convenção recomendada para commits

- `feat:` nova funcionalidade
- `fix:` correção
- `refactor:` melhoria estrutural sem mudar comportamento
- `docs:` documentação
- `test:` testes
- `chore:` manutenção e configuração

## Observação

Este arquivo registra critérios de apresentação e não substitui a documentação específica de cada repositório.
